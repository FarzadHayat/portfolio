SoulCert is a verifiable credential registry I built for **QUT IFB452 Blockchain Technology**. Qualifications usually sit in databases the institution controls, which are slow to verify and hard to trust long term. SoulCert issues them as **consensual soul-bound tokens** on Ethereum. They can't be transferred, can't be changed without detection, and only exist after the holder accepts.

The system uses a Manager / Ledger pattern to keep business logic separate from token storage. The **AttestationManager** is the single entry point. It handles proposals, acceptance, revocation and verification. The **CredentialRegistry** stores the tokens and blocks transfers, and only the manager can write to it. **IPFS** holds the encrypted credential data off-chain, so only a content reference and hash go on-chain.

Four roles use it. The **owner** deploys the system and authorises issuers. An **issuer** proposes credentials to holders. A **holder** accepts or rejects proposals, and can revoke per policy. A **verifier** checks a credential against on-chain records.

An issuer proposes a credential and the holder must accept before a token is minted. Rejecting discards the proposal. An authorised party can later burn a token if the burn policy agreed at issuance allows it. To verify, a verifier checks that the credential hash matches the on-chain record and that the expected wallet still holds the token. The holder shares the document off-chain, and verification itself happens on-chain. Full credential content never goes on the blockchain. Holders decrypt documents locally with keys derived from their wallet.

I built a React DApp with separate views for issuers, holders and verifiers. It connects to the contracts through MetaMask on a local Hardhat network. A test suite covers issuance, rejection, revocation and verification.
